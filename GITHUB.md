# Налаштування автоматичного оновлення на GitHub

Після цього налаштування карта оновлюватиметься **сама щопонеділка**, а ви просто відкриваєте посилання.

---

## Що станеться після налаштування

Щопонеділка о 6:00 за Києвом GitHub сам:

1. качає свіжий дамп ЄДРСР з data.gov.ua
2. відбирає нові рішення по десяти районних судах Києва
3. завантажує їх тексти, витягає адреси й час
4. геокодує
5. перебудовує карту
6. публікує на вашій сторінці

Ваш комп'ютер при цьому вимкнений. Нічого запускати не треба.

---

## Крок 1. Створити репозиторій

1. Відкрийте github.com, натисніть **New repository**
2. Назва: `karta-kyiv` (або будь-яка)
3. **Public** — це важливо, пояснення нижче
4. Створити

## Крок 2. Завантажити файли

Через GitHub Desktop, який у вас уже встановлений:

1. **File → Clone repository** → виберіть щойно створений
2. Скопіюйте в папку репозиторію: `src`, `.github`, `.gitignore`, `README.md`
3. Скопіюйте також **`data/events.csv.gz`** — це ваш накопичений стан, щоб 200 тисяч документів не качалися заново
4. У GitHub Desktop натисніть **Commit to main**, потім **Push origin**

> Якщо `data/events.csv.gz` у вас ще немає — запустіть один раз локально `1-DOWNLOAD`, він створить його наприкінці роботи.

## Крок 3. Увімкнути сторінку

1. У репозиторії: **Settings → Pages**
2. **Source:** виберіть **GitHub Actions**
3. Зберегти

## Крок 4. Дозволити запис

1. **Settings → Actions → General**
2. Внизу, розділ **Workflow permissions**
3. Обрати **Read and write permissions**
4. Зберегти

## Крок 5. Перший запуск

1. Вкладка **Actions** вгорі
2. Ліворуч оберіть **Оновлення карти**
3. Кнопка **Run workflow** праворуч
4. У полі `max_docs` залиште 20000
5. **Run workflow**

Перший запуск триває довше — від 20 хвилин до кількох годин, залежно від того, скільки документів треба добрати. Наступні будуть по 10–20 хвилин.

## Крок 6. Ваше посилання

```
https://ВАШ_НІК.github.io/karta-kyiv/
```

Це і є та адреса, яку ви даєте слухачам. Відкривається на телефоні, нічого встановлювати не треба.

## Про приховування коду — чесно

**Публічний репозиторій означає відкритий код.** Приховати його там неможливо, це сама суть публічного репозиторію.

Є три варіанти, обирайте свідомо:

### Варіант А. Все публічне (рекомендую)

Код видно. Хвилини Actions **необмежені**. Сторінка працює.

Чому раджу саме це: для звернень і для розмови з керівництвом відкритість методики є **перевагою, а не вадою**. Будь-хто може перевірити ваші розрахунки — це і робить їх аргументом. Закритий метод завжди можна відхилити фразою «а звідки ці цифри».

### Варіант Б. Приватний репозиторій

Код прихований. Але:
- сторінки на безкоштовному тарифі з приватних репозиторіїв **не публікуються** — потрібен платний GitHub Pro
- Actions обмежені 2000 хвилинами на місяць (нам вистачає, але запас менший)

### Варіант В. Два репозиторії

Приватний із кодом, публічний тільки зі зібраною папкою `site`. Автоматика кладе готове у другий.

Працює, але це вже потребує токена доступу і додаткового кроку. Робити є сенс тільки якщо приховування коду справді принципове.

---

## Скільки це коштує

Нічого. Публічні репозиторії — необмежені хвилини, сторінки безкоштовні.

Орієнтовний час одного запуску: 10–20 хвилин на тиждень.

---

## Що можна змінити

**Розклад.** У файлі `.github/workflows/update.yml` рядок:

```yaml
- cron: '0 3 * * 1'
```

Це понеділок, 03:00 UTC. Формат: хвилина, година, день місяця, місяць, день тижня. Наприклад `'0 3 * * *'` — щодня.

**Обмеження на запуск.** Змінна `max_docs` не дає завданню впертись у ліміт часу, якщо накопичилось багато нових документів. Залишок добереться наступного разу.

**Шар ризиків.** Оновлюється тільки за окремою вказівкою, бо міський простір змінюється повільно. Раз на кілька місяців запустіть вручну з галочкою `refresh_risks`.

---

## Що робити, коли щось зламається

Вкладка **Actions** → останній запуск → червоний хрестик показує крок, на якому впало. Натиснувши на нього, побачите повний вивід.

Найімовірніші причини:

**Не знайдено дамп.** На порталі змінилась структура набору. Тимчасове рішення: у **Settings → Secrets and variables → Actions → Variables** створіть змінну `EDRSR_URL` із прямим посиланням на архів.

**Overpass не відповідає.** Крок 2b пропускається без падіння — карта збереться зі старим шаром ризиків.

**Реєстр судових рішень блокує запити.** Можливий сценарій, якщо сервер обмежує доступ з хмарних адрес. Тоді доведеться повернутись до локального запуску кроку 1, а на GitHub залишити лише збірку карти.

## Про зростання даних

Файл `data/events.csv.gz` — це весь ваш накопичений стан. Приблизно 600 КБ на 200 тисяч записів. Навіть за кілька років зростання він залишиться в межах кількох мегабайт.

Кожне оновлення створює новий коміт. За рік їх буде близько п'ятдесяти. Це нормальний обсяг.

---

## Додавання нових джерел

Архітектура це передбачає: кожне джерело — окремий крок, який кладе результат у `data`, а `step3_map.py` збирає все разом.

Якщо колись з'явиться доступ до даних управління патрульної поліції, знадобиться лише новий скрипт `step0b_...py`, що приводить їх до того самого вигляду: адреса, дата, час, тип події. Решта конвеєра не змінюється.
