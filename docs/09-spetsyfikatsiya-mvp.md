# Специфікація MVP

**Статус: чернетка для перевірки даними.**  
**Дата: 08.09.2026.**

Це робочий контракт першої версії «Моєї вулиці». Він зводить у послідовний
план уже ухвалені продуктові, правові й етичні рішення. Це **не** рішення про
конкретний стек: його не можна ухвалювати до розмови з партнером
([`rishennya/0004-stek.md`](rishennya/0004-stek.md)).

Якщо цей документ суперечить `00-viziya.md`, пріоритет має візія. Якщо
суперечить правилам даних або права — пріоритет мають `03-dani-i-etyka.md` і
`02-pravo.md`.

---

## 1. Результат MVP

Користувач відкриває карту Києва, знаходить місце зумом або пошуком і бачить:

1. концентрацію **опублікованих у продукті подій** на різних масштабах;
2. за достатніх даних — проблемну зону як повторювану концентрацію подій
   одного типу;
3. події за адресою або в зоні;
4. коротку фабулу події, дату події, точність місця й посилання на конкретне
   судове рішення.

MVP не обіцяє «карту злочинності» та не оцінює безпеку місця. Кожне число
стосується лише подій, які пройшли конвеєр і можуть бути законно та коректно
показані.

**Перший географічний обсяг:** Київ.  
**Перший період для перевірки:** 2020–2026, якщо дамп містить повні тексти.  
**Перший тип доступу:** без реєстрації, FREE.

## 2. Ворота перед розробкою

| Ворота | Як перевіряємо | Наслідок, якщо не пройдено |
|---|---|---|
| Повні тексти в дампі | `readme_2026.pdf` і мала реальна вибірка архіву | Не починаємо основний конвеєр; переглядаємо джерело та продуктову гіпотезу |
| Право на використання | Запит ДСА щодо ліцензії й консультація щодо обмежень | Не публікуємо дані до письмової відповіді або іншої правової підстави |
| Щільність даних | Розрахунок на старому геокодованому масиві | Визначаємо реальні масштаби показу, а не вигадуємо їх |
| Якість кластерів | 20 кластерів оцінює фахівець | Якщо це шум, «проблеми» не входять до MVP |

Поки перші три ворота не пройдено, дозволена лише підготовка схеми,
тестових даних і конвеєра. Публічна карта не запускається.

## 3. Межі першого запуску

### Входить

- офіційний дамп ЄДРСР з `data.gov.ua`, без скрапінгу Реєстру;
- документи, з яких можливо виділити конкретну подію;
- тільки справи, що набрали законної сили;
- події з придатним місцем і посиланням на оригінал;
- карта, пошук адреси, картки соти / проблеми / місця / події;
- машинні фабули з обов'язковою позначкою та ручною перевіркою стартової
  вибірки;
- покриття даних і геоточність поруч із показниками;
- PRO-1 як окремий експеримент після того, як FREE доведе цінність.

### Не входить

- повна Україна, Android, сповіщення, акаунти, оплата;
- PRO-2 «що поруч» і статистичні зв'язки;
- прогнози, бали безпеки, безпечні маршрути, рейтинг будинків;
- автоматичне пояснення причин кластеру;
- події без придатної прив'язки, навіть якщо фабула добра;
- публікація повних текстів рішень у власній базі.

## 4. Дані та стани публікації

Конвеєр опрацьовує документ, але користувачу показує подію. Базовий шлях:

```
дамп → документ → справа → витяг події → місце → перевірки → фабула → публікація
```

Кожен об'єкт має незмінний внутрішній ідентифікатор, час створення, версію
методики та джерело. Повторний запуск того самого кроку не створює дублікатів.

| Стан події | Значення | Видима на карті |
|---|---|---|
| `vidkhyleno` | процесуальний документ або немає події | ні |
| `potrebuie_perevirky` | не вистачає впевненості для автоматичного рішення | ні |
| `neprydatne_mistse` | місце не знайдено, ненадійне або заборонене правилами | ні |
| `ochikuie_fabulu` | факт і місце придатні, але картка ще не готова | ні |
| `opublikovano` | пройдені всі обов'язкові перевірки | так |
| `znyato` | скасування рішення, звернення або виявлена помилка | ні |

Подію не можна перевести в `opublikovano`, якщо немає: `document_id`, URL
оригіналу, фінального статусу справи, категорії, рішення щодо придатності
місця, причини точності відображення та фабули з її статусом перевірки.

## 5. Контракт конвеєра

| Крок | Вхід | Результат | Обов'язкова метрика |
|---|---|---|---|
| Завантаження | посилання на дамп | незмінний знімок і контрольна сума | розмір, дата, кількість записів |
| Розбір | знімок | документ і метадані | успішно / помилки формату |
| Справа й статус | документи | справа, фінальний стан | частка невизначених статусів |
| Витяг події | текст документа | структурований факт «що / коли / де» | частка документів із подією |
| Категоризація | подія, статті, текст | категорія + версія таксономії | точність на ручній вибірці |
| Місце | витяг місця | нормалізована адреса, геометрія, впевненість | знайдено / геокодовано / відхилено |
| Приватність | місце + контекст | точка, сота, сегмент або виключення | причина зниження точності |
| Фабула | допустимий фрагмент факту | текст, джерело генерації, рев'ю | частка ручної перевірки, помилки |
| Публікація | усі перевірки | подія, доступна API | кількість за статусом |

Сирий текст потрібен лише під час обробки. У робочій базі для продукту не
зберігаємо повний текст рішення; зберігаємо мінімально необхідні витяги,
походження полів і URL оригіналу.

### Витяг факту

Для кожного поля зберігається: значення, фрагмент-джерело або його координати
в документі, метод витягу, впевненість і версія правила. Так можна перевірити
фабулу й виправити помилку без «довіри до моделі».

Невизначене поле лишається `null`; його не можна підміняти правдоподібним
значенням. Дата події, дата рішення та дата появи документа — різні поля.

### Дедуплікація

Одна справа може містити кілька інстанцій, а одна реальна подія — кілька
документів. Перший рівень — групування за номером справи й визначення
чинного документа. Другий — ручно перевірена евристика для подій з різних
справ: категорія, час, місце та фактичний опис. Автоматична підозра на
дублікат **не зливає** події без перевірки: вона лише переводить їх у чергу.

## 6. Географічний контракт

Місце події спочатку класифікується за роллю в тексті: місце події, проживання,
робота, майно, установа або невідомо. На карту може потрапити тільки перший
тип із достатньою впевненістю.

| Умова | Відображення |
|---|---|
| багатоквартирний будинок або публічне місце | точка / будинок |
| перехрестя, парк, дорога | точна точка |
| приватний сектор з 8+ адресами в зоні | сота або сегмент вулиці |
| приватний сектор із менш ніж 8 адресами | не точніше за село / вулицю; за потреби не публікуємо |
| подія за місцем проживання | не публікуємо |
| геокодування ненадійне | не публікуємо на карті |

Це реалізація рішення про 8 адрес, а не налаштування інтерфейсу. API віддає
лише `display_geometry`, ніколи не приховану точну геометрію приватного місця.

## 7. Карта і поведінка інтерфейсу

Карта має один стан камери: місто, зум, центр, фільтри й період. Він
серіалізується в URL, тому посилання відтворює той самий перегляд.

| Рівень зуму | Дані на карті | Дія користувача |
|---|---|---|
| місто | загальне покриття та концентрація | наближає або шукає |
| середній | шестикутні соти з кількістю й періодом | відкриває коротку картку |
| ближчий | проблемні зони, лише якщо пройдено методичні пороги | відкриває пояснення показника |
| адресний | доступні місця та склад подій | відкриває профіль місця |
| подієвий | список подій для вибраного місця | читає фабулу й джерело |

Точні пороги зуму залежать від щільності даних і встановлюються після
вимірювання. В інтерфейсі немає перемикача «Події / Проблеми»: дані змінює
тільки масштаб.

Картка події містить лише: категорію, дату з її точністю, відображене місце,
фабулу, позначку «за матеріалами судового рішення», статус автоматичного
переказу, посилання на оригінал та дію «повідомити про помилку / звернутися
щодо видалення».

## 8. Контракт API

Назви маршрутів і формат можуть змінитися з обраним стеком; наведено
стабільні можливості, які має забезпечити API.

| Можливість | Мінімальний вхід | Мінімальна відповідь |
|---|---|---|
| Пошук | рядок, межа міста | нормалізовані місця, тип, координата відображення |
| Дані для карти | межі, зум, період, категорії | соти / зони / місця відповідного рівня, покриття |
| Профіль соти | ідентифікатор соти, період | кількість, категорії, проблеми, покриття |
| Профіль місця | ідентифікатор місця | відображена геометрія, події, склад категорій |
| Подія | ідентифікатор події | тільки публічні поля картки й URL джерела |
| Методика | версія | правила, пороги, дата обчислення |
| Звернення | тип, контакт, опис, посилання | номер звернення й строк відповіді |

Усі числові агрегати повертають період, кількість подій, покриття, геоточність
і версію методики. Якщо даних недостатньо, API повертає явний стан, а не нуль.

## 9. Проблеми, сигнали й аналітика

Для MVP потрібно розділити три рівні:

- **агрегат** — чесна кількість подій у соті, місці чи періоді;
- **сигнал** — порівняння з базою, яке має територію, період, кількість,
  впевненість, покриття і версію методики;
- **проблема** — сигнал про просторово-часову концентрацію однорідних подій,
  що пройшов задані пороги.

Поки не буде ручно перевірено кластерів, карта може показувати агрегати й
покриття, але не називати нічого «проблемною зоною». Це не зменшення обсягу —
це захист від хибного продуктового твердження.

PRO-1 додається після перевірки FREE: динаміка за порівнюваних періодів,
порівняння двох місць, деталізація сигналу, рейтинг проблем і фільтри. Будь-яка
динаміка блокується, якщо покриття періодів непорівнюване.

## 10. Фабули та редакційний контроль

Фабула генерується з дозволених структурованих фактів і визначених фрагментів
джерела, а не з «враження від справи». Перед публікацією автоматична перевірка
має відхилити текст, якщо він:

- додає число, дату, час, адресу, стать, вік або мотив, яких немає у витягах;
- називає особу або сукупність деталей, що робить її впізнаваною;
- описує результат суду замість події як головний зміст;
- стверджує причинність або оцінює місце.

Перші кілька сотень фабул перевіряються людиною. Для тяжких або чутливих
категорій людська перевірка є умовою публікації до окремого документованого
рішення про інше.

## 11. Якість, безпека та операції

Перед будь-яким публічним запуском потрібні:

- журнал запусків конвеєра, помилок і версій правил;
- вибірка для ручної перевірки: категорія, дата, роль адреси, координата,
  точність і фабула;
- автоматичне зняття події при зміні статусу справи;
- журнал звернень про видалення та контроль 10 робочих днів;
- резервна копія бази, контроль доступу й мінімізація персональних даних;
- окрема тестова база без справжніх персональних даних для розробки;
- сторінка методики й видима атрибуція ЄДРСР / ДСА та внесених змін.

## 12. Критерії готовності та метрики рішення

### Внутрішня готовність

1. Обрано і записано стек; схема створюється повторювано.
2. Конвеєр Києва можна перезапустити без дублікатів.
3. Для кожної опублікованої події є чинне джерело, категорія, рішення про
   географічну придатність та перевірювана фабула.
4. Правило 8 адрес перевіряється обмеженням даних і тестами.
5. Кожна цифра на карті розкривається до періоду, кількості та покриття.
6. Невизначеність відображається як «недостатньо даних», не як нуль.

### Перевірка продуктової гіпотези

Перед оплатою вимірюємо щонайменше:

| Питання | Сигнал |
|---|---|
| Чи карта зрозуміла | частка сесій із зумом, пошуком або кліком по карті |
| Чи цікавлять події | відкриття карток і дочитування фабули |
| Чи люди досліджують місце | переходи сота → місце → подія |
| Чи є повторна цінність | повернення до збереженого або надісланого URL після появи цієї функції |
| Чи є попит на PRO | перегляд пояснення аналітики та конверсія тестової пропозиції |

Цільові пороги не вигадуємо до першої малої вибірки. Спочатку фіксуємо базову
лінію, розмір вибірки й період спостереження; лише потім ухвалюємо рішення про
PRO або наступне місто.

## 13. Послідовність робіт

1. Пройти чотири ворота з розділу 2 і записати результати.
2. Обрати стек і завершити фізичну схему даних.
3. Зібрати малий наскрізний зріз: документи → 50–100 вручну перевірених подій
   → карта.
4. Виміряти геокодування, щільність і кластери на Києві.
5. Лише після прийнятної якості масштабувати конвеєр на 2020–2026.
6. Запустити закритий тест FREE; за результатами вирішити про PRO-1.

Ця послідовність важливіша за швидкість інтерфейсу: без придатних текстів,
місць і кластерів гарна карта лише зробить помилку помітнішою.
