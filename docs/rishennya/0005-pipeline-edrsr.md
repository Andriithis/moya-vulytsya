# Рішення 0005 — pipeline ЄДРСР

Статус: прийнято
Дата: 2026-09-10

## Архітектура

Джерело даних — офіційний щорічний кумулятивний архів ЄДРСР на data.gov.ua. ZIP/CSV не є робочим сховищем API.

Робоче сховище: PostgreSQL + PostGIS.

Основні сутності:
- `source_snapshot`
- `pipeline_run`
- `document`
- `case_record`
- `event`
- `location`
- `event_location`

`event_location.role` розрізняє `EVENT_LOCATION`, `COURT`, `RESIDENCE`, `WORKPLACE`, `PROPERTY`, `INSTITUTION`, `OTHER`, `UNKNOWN`.

На карту потрапляють лише зв'язки з роллю `EVENT_LOCATION`.

## Інкрементальність

Поточний архів року є кумулятивним snapshot від початку року до кінця попереднього дня. Тому відсутність документа в новому snapshot не означає видалення. Статус документа береться з поля `status` ЄДРСР: `1` — активний, `0` — неактивний/видалений.

Snapshot ідентифікується ресурсом, датою/версією та hash. Якщо snapshot уже оброблений — pipeline завершується без повторної обробки.

Для документа зберігаються `edrsr_id` (`doc_id`), метадані джерела та hash релевантних полів/рядка. Повторно запускаються extraction/classification/geocoding лише для нових або змінених документів.

На межі року pipeline обробляє новий рік; попередній рік може бути повторно перевірений, доки ЄДРСР публікує зміни до нього.

## Етапи pipeline

1. Знайти актуальний офіційний ресурс ЄДРСР.
2. Перевірити hash/версію snapshot.
3. Завантажити ZIP та провалідувати структуру.
4. Зберегти raw snapshot поза Git.
5. Зареєструвати `source_snapshot` і `pipeline_run`.
6. Upsert документів за `edrsr_id`.
7. Визначити нові/змінені документи.
8. Витягнути події, ролі адрес та інші нормалізовані сутності.
9. Геокодувати тільки адреси, класифіковані як `EVENT_LOCATION`, з confidence.
10. Upsert подій і локацій, виконати dedup.
11. Перерахувати похідні дані проблем/зон.
12. Записати метрики pipeline і результат перевірок.

## Принципи

- `event date` не ототожнюється з `decision date`.
- Адреса суду сама по собі не є місцем події.
- Адреса проживання, роботи, майна або установи не стає точкою події.
- Низька впевненість геокодування не повинна автоматично створювати точку на карті.
- Дублікати документів/справ/подій мають оброблятися окремо.
- API читає PostgreSQL/PostGIS; карта не читає ZIP/CSV напряму.
- `data/events_test.db.gz` зберігається як тестовий fixture.

## Міграція існуючого коду

`src/step0_fetch_dump.py` мігрується поступово: ingestion/metadata/hash → `source_snapshot` → upsert `document` → тимчасовий compatibility export → переведення downstream на DB → видалення compatibility export після стабілізації.
