# ЗВІТ-161 — Сервер продажу: доробки з MV-173

Виконавець — хмара, 20.11.2026. Завдання — `ZAVDANNYA-161.md`. Гілка `claude/trusting-albattani-m52fzl`, по коміту на крок.

## Коротко

Усі шість кроків зроблено, кожен — з тестами. Тести сервера продажу: **111 з 111** (було 97, додано 14). Тести Python
(`python -m unittest discover -s tests`, як у перевірці GitHub): **555, усі зелені** (35 пропущено — як і раніше, без даних
випуску). На справжньому Cloudflare, справжній пошті й LiqPay **нічого не перевірено** — лише місцево, на справжньому коді й
справжній схемі бази.

## 1. Вхід кнопкою

- `GET /kabinet/vkhid/?t=…` лише показує сторінку «Вхід у кабінет» з кнопкою «Увійти» (без кукі, не кешується); якщо посилання
  застаріле — «надішлемо нове». Сам вхід — `POST /kabinet/vkhid/uviity`, лише з нашого сайту, під тим самим лімітом запитів.
- Лист тепер каже: «Відкрийте посилання й натисніть «Увійти»».
- Тест «поштовий сканер тричі відкрив посилання — вхід не згорів; кнопка з чужого сайту — 403; людина натиснула — увійшла».
- Знімок сторінки на телефоні (місцевий сервер з файлами сайту) — подивився очима: заголовок, пояснення, кнопка, підвал.

## 2. Ліміт описів — порада щодо числа

**Порада — 300 на добу.** Підстава: опис підтягується, лише коли людина відкриває панель адреси (`dani-edrsr/site_src/core.js`:
файл клітинки береться при першому відкритті, далі — з пам'яті браузера; клітинка ≈ 500 × 500 м). Людина за вечір дослідження
відкриває десятки клітинок, рідко сотню. Київ — кілька тисяч клітинок з подіями (точне число не рахував — без випуску), тож
скачати все за день не вийде, а за 10+ днів — вийде, і партнер щодня бачитиме лист. Якщо партнер побачить, що справжні люди
впираються, — підняти `KARTA_NA_DEN` без нової викладки коду. Від «злив за місяць» ліміт не захищає — це вже водяний знак
(`ZVIT-156`, п. 1б), окреме рішення.

Лічильник — таблиця `karta_zavantazhennia` (людина, день, число), стирається через тиждень; у політиці додано рядок.

## 3. Лист «Оплату отримано»

Шаблон — `site/worker/prodazh/lysty.js` (`oplatuOtrymano`), різний текст для довідки/звіту, пакета «3 довідки», підписки, ОСББ,
юриста. Повтор сповіщення платіжного сервісу другого листа не шле. Не вдалося надіслати лист — оплату однаково зараховано.
Якщо партнер задасть `POSHTA_KONTAKT`, у листі буде «Написати нам: …»; без неї — посилання на оферту. В оферту (розд. 4)
додано пункт «Підтвердження»; у політиці — мета листів сервісу пошти.

## 4. Стирання за строками

`logika.js` → `styratyZaStrokom`, щоденний розклад Workers (`17 2 * * *`; у режимі «скоро» тепер теж є розклад).
- **Пошта без покупки:** людина, у якої всі замовлення незавершені й старші за 30 днів, немає підписки, довідок, «Стежу», балів
  і входу за 30 днів, стирається так само, як кнопкою «Видалити мої дані». Незавершені замовлення лишаються без пошти.
- **Звернення:** через рік після відповіді (поле «закрито»). Без відповіді — не стирається.
- **«Скоро»:** через пів року після листа про запуск або (для товарів, що вже продаються) після запуску продажу.
- **Передзамовлення:** лише Київ — через пів року після запуску; інші міста — вручну, коли запустимо там.
- **Запуск продажу** — змінна `DATA_ZAPUSKU` або, без неї, перша справжня оплата (не тестова й не за бали).

Список для Микити: рядок «стирати вручну раз на місяць» замінено на «сервер робить сам; вручну — інші міста й відкликання згоди».
Політика, розд. 5: додано «пошта без оплати — 30 днів» і «за строками стежить сервер».

## 5. Позачергове прибрання події

**Як працює.** Партнер входить у кабінет своєю поштою (`POSHTA_PARTNERA` або список `PARTNERY`; лист входу приходить і без
покупок) → «Звернення людей». Там: звернення (відкриті — зверху, контакт людини, пояснення — лише текстом), поле з посиланням
на рішення (якщо людина дала посилання на рішення — уже вписане), «Прибрати подію зараз», «Відповіли — закрити», журнал
прибраних з «Повернути». Для скриптів — те саме з ключем `ADMIN_KLIUCH`.

**Що зникає одразу** (сервер відфільтровує рішення на льоту, `prodazh/prybrannia.js`):
- карта підписника (R2): описи клітинки й «події адреси» — без цієї події;
- колоди ігор: «Вгадай», «Вулиця дня», «Літопис» (і зі списків вулиць), «Детектив», «Кваліфікуй», «Кар'єра» — шість файлів
  `/ihry/*.json` тепер ідуть через скрипт (`site/khostynh.py`, `KOLODY_IHOR`; тест звіряє цей список зі збирачем сайту).

**Відхилення від завдання — сторінки будинку й вулиці.** Там подій немає взагалі — лише числа (MV-99, MV-100): ні опису, ні
посилання, тож упізнати й прибрати там конкретну подію нема що. Число зменшиться з наступним випуском. Переписувати числа
на льоту (і всі похідні: роки, групи, порівняння з сусідами) — крихко й не варте ризику; не робив.

**Що НЕ зникає одразу (⚑ центральному чату):**
1. **Нові довідки й звіти.** Генератор бере події з випуску, тож довідка, складена до наступного випуску, ще може містити
   прибрану подію. Оферта (розд. 7) обіцяє, що в наступних довідках її не буде. Для закриття — маленьке завдання в
   `dani-edrsr`: генератор пропускає рішення зі списку `GET /api/vnutr/prybrani` (ключ видавача; адресу вже зроблено й
   перевірено тестом). Сам `dani-edrsr` не чіпав — межа завдання.
2. **Точка на карті підписника** лишається до наступної версії карти (у панелі адреси подія вже зникла).
3. **Наступний випуск:** журнал (`GET /api/admin/prybrani` або вивантаження `prybrani_podii`) треба перенести у вилучення
   конвеєра `dani-edrsr/config/vyluchennia.json`. Якщо забудуть — фільтр сервера однаково не покаже подію.

Знімок кабінету звернень на телефоні — подивився очима після прибрання (повідомлення, журнал із кнопкою «Повернути»).

## 6. Android

`android/twa-manifest.json`: `enableNotifications: false`. Перевірив генератором Bubblewrap (той самий, що в `android/zibraty.js`,
лише крок «згенерувати проєкт», без Gradle): з `false` в `AndroidManifest.xml` немає `POST_NOTIFICATIONS` і запиту дозволу;
з `true` — є. Повну збірку `.aab` не робив — у хмарі немає Android SDK; **прототип `app-prototyp.apk` від 19.11 ще зі
сповіщеннями — перезібрати** перед поданням. `docs/ANDROID.md` (анкета безпеки, дозволи, розд. 6 «не зараз») і тест
`tests/test_android.py` оновлено.

## Помічене поза завданням (не виправляв)

- Політика, розд. 5: «записи про платежі — 3 роки». Сервер зберігає знеособлені замовлення без строку — автоматичного
  стирання через 3 роки немає. Не терміново (перші 3 роки), але колись — у щоденне прибирання.
- `site/worker/testy/mistsevyi.mjs` відкидав відносний шлях до сайту (стилі не вантажилися) — працює лише з абсолютним.
  Не чіпав, лише додав партнера для кабінету звернень.

## Чесно: що не перевірено

- Нічого не викладалось на Cloudflare: розклад, прив'язки, `run_worker_first` для колод, швидкість фільтра на справжній
  колоді (розбір JSON на кожен запит — лише коли є хоч одне прибрання) — не міряно.
- Листи — у заглушку пошти; справжній сервіс листів не перевірено.
- Поштові сканери — змодельовано запитом GET; на справжньому Outlook не перевірено.
- Ліміт 300 — оцінка з коду карти, без даних про справжніх користувачів.
- Перевірка асистента — не незалежна.
