# «Для бізнесу»: доступ до бази за особистим посиланням

ZAVDANNYA-157, 20.11.2026. Рішення 19.11 (центральний чат з Андрієм): компаніям — база в користування на місяць або рік
(MV-3, MV-92); спершу **особисте посилання на свіжу копію з обмеженим строком**, доступ для програм (API) — пізніше за запитом.
Договір — `docs/DOHOVIR-LITSENZIIA-BIZNES.md`. Знімки сторінки — `docs/znimky-157/`.

## 1. Як це працює — одним абзацом

Компанія лишає запит на сторінці `/biznes/` → Микита відповідає й підписує договір → заводить клієнта (`k1`, `k2`…) →
щомісяця після нового випуску збирає копію саме для цього клієнта й кладе її в приватне сховище → видає посилання на
N днів → компанія відкриває сторінку зі своєю назвою і забирає файли. Договір закінчився чи порушено — одна команда
вимикає клієнта й усі його посилання одразу.

## 2. Що в копії (поля) і чого немає

Збирає `dani-edrsr/src/kopiia_biznesu.py` (правило S-Д.14 у `dani-edrsr/SPECYFIKATSIYA.md`). Файли: `baza.db` (SQLite),
`csv.zip` (ті самі таблиці CSV + опис), `OPYS.md` (опис полів і умови коротко), `SHA256SUMS`.

| Таблиця | Що |
|---|---|
| `podii` | дата (немає дати події — дата рішення з позначкою), година, вид, група як на карті, стаття, опис (той самий очищений показ, що в підписці — без імен суддів, поліцейських, захисників), переказ ШІ і результат — коли будуть у випуску, позначки `chutlyva` і `domashnie`, адреса, точність, координати (без точного місця — сота), суд словами, дата рішення, номер справи, посилання на рішення |
| `problemy`, `problemy_podii` | місця, де однотипні події повторюються, і які події туди входять |
| `skarhy_1551` | звернення до 1551 по будинках — числом за групою і періодом (якщо дати `--budynky`), без тексту заявника |

**Чутливе — як у підписці** (MV-69, MV-102, MV-104): домашнє насильство, статеві, щодо дітей — нарівні, з позначкою, щоб
компанія могла їх відфільтрувати; місце й опис — як оприлюднив суд (у пробному випуску 08.11 у таких 39 подій їх і так немає).

**Не входить ніколи:** імена (що суд приховав — не відновлюємо), повні тексти рішень, внутрішні номери документів конвеєра,
текст звернень 1551; події виду «поза групами», без посилання на рішення і **видалені за зверненням** — видалення діє і для
компаній (договір, розд. 5).

**Позначка клієнта.** Номер події в копії — свій у кожного клієнта (і сталий для нього з місяця в місяць, щоб він міг
оновлювати свої таблиці). Знайшли копію в мережі — за номерами видно, чия вона.

Пробний випуск 08.11 (перевірено): 144 273 події, з них 70 552 з точним місцем, 138 758 з описом; 80 проблем; `baza.db`
151 МБ, `csv.zip` 26 МБ; збирання ≈ 3 хв.

## 3. Чому так: варіанти й порада

| Варіант | Плюси | Мінуси |
|---|---|---|
| **А. Своє посилання через наш скрипт на Cloudflare (зроблено, порада)** | вимикається миттєво; строк і ліміт завантажень перевіряє сервер; кожне завантаження записано; ключ у базі лише хешем; один набір ключів (той самий сервер продажу) | файл іде через скрипт Workers (для 150 МБ це нормально; ліміту розміру відповіді немає) |
| Б. «Підписані посилання» самого сховища R2 (S3) | файл іде напряму зі сховища | відкликати до кінця строку не можна (до 7 днів); потрібен ще один ключ доступу до сховища; завантажень не видно |
| В. Надсилати файл листом / через диск Google | просто | 150 МБ листом не пройде; диск — без строку, без обліку, легко переслати |

Порада — **А**. Слово «підписані» з рішення 19.11 виконано по суті: посилання з випадковим ключем на 160 біт, строком і
лімітом, яке сервер перевіряє за базою.

Строк посилання — **7 днів, до 20 завантажень** за замовчуванням (можна 1–31 день, 1–200 завантажень); ніколи не довше за
договір. Річний клієнт — нове посилання щомісяця разом з новою копією.

Адреси сервера: `POST /api/forma/biznes`; `/api/admin/biznes/{klient, klient/kN, posylannia, vymknuty, klienty, zapyty.csv,
zavantazhennia.csv}` (ключ партнера `ADMIN_KLIUCH`); `GET /kopiia/<ключ>/` і `/kopiia/<ключ>/<файл>`. Працює і в режимі
«скоро» (оплата на сайті не потрібна — договір і рахунок у партнера). Нагадування «договір спливає за 14 днів» — щодня, лише в
режимі `tak` (розклад Cron є лише там).

## 5. Для Микити: покроково

Один раз:
1. Cloudflare → R2 → створити сховище **`moya-vulytsya-biznes`** (приватне, без публічного доступу).
2. Оновити базу D1: `npx wrangler d1 execute moya-vulytsya-prodazh --remote --file=site/worker/prodazh/skhema-157.sql`.
3. Змінна викладки **`MV_BIZNES_R2=tak`** (або `--biznes-r2` у `site/zibraty_sait.py`) і викласти сайт (`docs/ZAPUSK-SAITU.md`).
4. На своєму комп'ютері — змінні `MV_ADRESA_SAITU=https://moyavulytsya.com.ua` і `MV_ADMIN_KLIUCH=<секрет ADMIN_KLIUCH>`
   (лише в середовищі, не у файлах).

Коли прийшов запит (лист «Новий запит „Для бізнесу“»):

```bash
python site/prodazh/biznes_klienty.py zapyty
```

Підписали договір:

```bash
python site/prodazh/biznes_klienty.py novyi "ТОВ «Назва»" ofis@firma.ua --tarif rik --do 2027-11-30 --dohovir Л-1/2026
```

Щомісяця після нового випуску (на ПК, де лежить `events-<дата>.db`), для кожного клієнта:

```bash
python ../dani-edrsr/src/kopiia_biznesu.py events-2026-12-01.db kopii --klient k1
```

```bash
python site/prodazh/biznes_r2.py kopii/kopiia-2026-12-01-k1 --zavantazhyty
```

```bash
python site/prodazh/biznes_klienty.py posylannia k1 --dniv 7
```

Посилання показується один раз — надіслати на пошту з договору. Продовжити, вимкнути, подивитися:

```bash
python site/prodazh/biznes_klienty.py prodovzhyty k1 --do 2028-11-30
```

```bash
python site/prodazh/biznes_klienty.py vymknuty k1 --prychyna "договір розірвано"
```

```bash
python site/prodazh/biznes_klienty.py spysok
```

Посилання переслали чужим — `vymknuty k1 --lyshe-posylannia`, потім нове `posylannia`.

## 6. Чого не перевірено

- На справжньому Cloudflare (R2, D1, Workers) — не викладалось; перевірено місцевим сервером із справжнім кодом Workers,
  SQLite замість D1 і «сховищем» на диску.
- Віддача файла 150 МБ через Workers — не міряна на Cloudflare (у Workers немає ліміту розміру відповіді, але швидкість не
  перевірено).
- Договір — без юриста (MV-152); ланцюжок прав Андрій → партнер ще не оформлено.
- Скарги 1551 у копії — лише з `--budynky` (зведення `budynky_sait.py`), на пробних даних не збирали.
