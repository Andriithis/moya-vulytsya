# Фаза 2: доказовий контекст адрес, v2

Дата: 14.09.2026. Обсяг: надійне збереження результату витягування та другий
консервативний набір правил адрес. UX не змінювався.

## Що змінилося від v1

- Витягувач розпізнає окремі конструкції, де адреса стоїть перед описом дії,
  та не розриває контекст на скороченнях `м. Київ` і `КУпАП`.
- Заборонні ролі `COURT`, `RESIDENCE`, `WORKPLACE`, `PROPERTY` та `INSTITUTION`
  мають пріоритет над словами, схожими на опис події.
- У режимі PostgreSQL успішний результат зберігається в приватній таблиці
  `document_extraction` разом із `source_row_hash`, SHA-256 тексту, версією
  правил, сумісним рядком і всіма кандидатами адрес.
- Запис checkpoint і `needs_processing=FALSE` відбуваються в одній транзакції
  з блокуванням документа. Збій до commit не завершує завдання.
- Чиста локальна SQLite відновлюється тільки з checkpoint активного документа,
  чий `source_row_hash` і версія extractor-а досі збігаються.
- Міст SQLite → PostgreSQL повторно звіряє `source_row_hash` під блокуванням.
  Якщо документ змінився пізніше або біля кандидатів немає хешу, старий
  автоматичний `EVENT_LOCATION` відкликається і результат не синхронізується.
- Помилка завантаження документа не записується як успішний checkpoint і
  лишає документ для безпечного повтору.

Це не означає завершення Фази 2. Геокодування, confidence, адміністративні
межі, нормалізація перейменованих вулиць, незалежний ручний QA та production
backfill залишаються відкритими.

## Міграція 0003

Перед оновленням зробіть резервну копію production PostgreSQL. Потім:

1. Застосуйте попередню міграцію `db/migrations/0002_events_locations_bridge.sql`,
   якщо її ще немає.
2. Застосуйте `db/migrations/0003_document_extraction.sql` від ролі власника
   схеми. SQL можна виконати повторно, бо він використовує
   `CREATE TABLE IF NOT EXISTS`.
3. Переконайтеся, що робоча роль pipeline має потрібні права на таблицю.
   Міграція навмисно відкликає права `PUBLIC`; публічна API-роль не повинна
   читати повні контексти.
4. Лише після міграції задайте `DATABASE_URL` для step1. Без таблиці
   `document_extraction` PostgreSQL-режим завершиться помилкою; прихованого
   fallback до SQLite немає.
5. Перший прогін відновить сумісну SQLite з чинних checkpoint, а документи без
   checkpoint поточної версії знову поставить у чергу.

`db/schema.sql` уже містить 0003 для створення нової БД з нуля. Інтеграційний
тест застосовує міграцію двічі до наявної схеми й перевіряє запис checkpoint.

## Режими запуску

Без `DATABASE_URL` зберігається сумісний локальний режим `kyiv_*.csv` + SQLite.
Він не має довготривалого PostgreSQL checkpoint. Кандидати без прив'язаного
`source_row_hash` не можуть бути підвищені до `EVENT_LOCATION` під час
подальшого PostgreSQL sync.

З `DATABASE_URL` джерелом черги є PostgreSQL. Успішне витягування завершує
завдання атомарно; помилка, аварія до commit або зміна source лишає його в
черзі. Після відновлення локального стану старі координати очищаються і мають
бути отримані заново тільки для підтверджених місць.

Production PostgreSQL/PostGIS, секрет `DATABASE_URL`, приватне довготривале
сховище і weekly schedule **не налаштовані**. Підтримка цього режиму в коді не
є доказом робочого deployment.

## Перевірений обсяг

- Локально: 44 тести пройшли; 12 PostgreSQL-тестів без `TEST_DATABASE_URL`
  коректно пропущені.
- Окремий CI job має запустити PostgreSQL-тести в PostGIS 16 і перевірити
  повтор, rollback, чисту SQLite, деактивацію, зміну джерела, stale sync та
  міграцію. Результат CI останнього commit треба перевірити після push.
- Розробницький QA містить 13 кешованих уривків із уже наявного
  `FABULA_REZULTAT.txt`: 10 очікуваних місць, 8 правильних, 0 неправильних,
  2 пропущені. Розмітку зробив асистент; це не незалежний людський QA і не
  production precision.

Перевірки:

```text
python -m unittest discover -s tests -v
python -m pipeline.location_qa
```

Контексти, локальні SQLite та raw-рішення не публікувати в Git або публічних
Actions artifacts.

Завершальне рев’ю 14.09.2026: старі `FABULA_REZULTAT.txt`, архів SQLite та
фабули вилучено з поточного дерева Git зі збереженням локальних копій.
