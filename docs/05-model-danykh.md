# Модель даних

> **Статус: чернетка.** Остаточна схема — після вибору технологій
> ([`rishennya/0004-stek.md`](rishennya/0004-stek.md)).
> Але **склад сутностей і обов'язкові поля вже зафіксовані** — вони не залежать
> від того, яку базу оберемо.

---

## 1. Сутності та їх зв'язки

```
ДОКУМЕНТ ──належить──▶ СПРАВА
   │                      │
   │                 має статус
   │                      ▼
   └──описує──▶ ПОДІЯ ──має──▶ ЛОКАЦІЯ
                  │
                  ├──має──▶ ІСТОРІЯ (переказ для читача)
                  └──має──▶ КАТЕГОРІЯ
```

Окремо, не пов'язані з конкретною подією:

```
СИГНАЛ (територія + період + категорія)
ГІПОТЕЗА (пояснення сигналу, БЕЗ координат)
```

---

## 2. Документ

Один судовий документ з ЄДРСР.

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | наш внутрішній ідентифікатор |
| `edrsr_id` | **так** | номер документа в ЄДРСР |
| `edrsr_url` | **так** | посилання на оригінал |
| `case_number` | так | номер справи |
| `court` | так | суд |
| `doc_type` | так | вирок / постанова / ухвала / рішення |
| `instance` | так | перша / апеляційна / касаційна |
| `date_published` | так | дата появи документа в реєстрі |
| `date_decision` | так | дата ухвалення рішення |
| `articles` | ні | статті |

Повний текст **не зберігаємо** — він доступний за `edrsr_url`.

## 3. Справа

Усі документи однієї справи. Потрібна, щоб не показувати скасований вирок.

| Поле | Обов'язкове | Опис |
|---|---|---|
| `case_number` | так | номер справи |
| `status` | **так** | `в процесі` / `набрало законної сили` / `скасовано` / `змінено` |
| `final_document_id` | ні | документ, який визначає поточний стан |
| `status_checked_at` | так | коли востаннє перевіряли статус |

**Правило:** на карту потрапляють події лише зі справ у статусі
`набрало законної сили`. Зміна статусу на `скасовано` автоматично знімає
подію з карти.

## 4. Подія

Те, що сталося в реальності. **Це те, що бачить користувач.**

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | |
| `document_id` | **так** | звідки взято. **Без цього запис не зберігається** |
| `case_number` | так | |
| `category_id` | так | наша категорія |
| `date_event` | ні | коли сталося |
| `date_event_precision` | так, якщо є дата | `день` / `місяць` / `рік` / `період` |
| `time_of_day` | ні | ранок / день / вечір / ніч — якщо визначено з тексту |
| `location_id` | ні | якщо не вдалося визначити — подія є, але не на карті |
| `raw_fabula` | так | фабула, як її написав суд |
| `excluded` | так | чи виключена з показу |
| `exclusion_reason` | якщо `excluded` | причина, з переліку в `03-dani-i-etyka.md` |

**Обмеження, яке треба закласти в базу:**
подія без `document_id` не може бути збережена. Це технічна реалізація правила
«факт має посилання на рішення».

## 5. Локація

Ніколи не просто координата.

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | |
| `lat`, `lon` | так | координата |
| `precision_level` | **так** | `точка` / `будинок` / `сота` / `сегмент вулиці` / `вулиця` / `мікрорайон` / `населений пункт` |
| `confidence` | **так** | 0–1, наскільки впевнені в геокодуванні |
| `raw_address` | так | текст адреси, як він був у рішенні |
| `normalized_address` | ні | після нормалізації |
| `address_count_in_area` | **так** | скільки адрес у зоні навколо точки |
| `is_residential_private` | так | чи приватний сектор |
| `display_geometry` | так | що саме малюємо: точку чи соту |

**Обмеження:**
- координата без `confidence` не зберігається;
- якщо `address_count_in_area < 8` і `is_residential_private = true`, то
  `precision_level` не може бути `точка` або `будинок`. Це технічна реалізація
  правила 8 адрес.

## 6. Історія

Наш переказ події для читача. **Окремий авторський твір** — це важливо
для захисту прав ([`02-pravo.md`](02-pravo.md), розділ 5).

| Поле | Обов'язкове | Опис |
|---|---|---|
| `event_id` | так | |
| `title` | так | заголовок |
| `text_short` | так | коротко, 1–2 речення |
| `text_full` | ні | розгорнута історія |
| `generated_by` | так | `машина` / `людина` / `машина + перевірка людиною` |
| `reviewed_by` | ні | хто перевірив |
| `reviewed_at` | ні | коли |
| `published` | так | чи показується |

**Правило:** історія з `generated_by = машина` без перевірки показується з
позначкою «автоматичний переказ». Для тяжких статей — тільки після перевірки
людиною.

## 7. Сигнал

Статистична закономірність. **Окрема таблиця, не поле в події.**

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | |
| `territory_type` | **так** | зона / вулиця / мікрорайон / район / місто |
| `territory_id` | **так** | яка саме територія |
| `period_from`, `period_to` | **так** | період |
| `category_id` | так | категорія подій |
| `event_count` | **так** | скільки подій |
| `comparison_base` | **так** | з чим порівнюємо: сусідні території / місто / попередній період |
| `comparison_value` | так | значення бази |
| `level` | так | `низька` / `звичайна` / `підвищена` / `висока` / `недостатньо даних` |
| `confidence` | **так** | рівень упевненості |
| `coverage` | **так** | покриття даних на цій території за цей період |
| `method_version` | так | версія методики розрахунку |

**Обмеження:** сигнал без `comparison_base`, `event_count`, `period` і
`territory` не зберігається. Це технічна реалізація правила «сигнал завжди
пояснений».

## 8. Гіпотеза

Можливе пояснення сигналу.

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | |
| `signal_id` | так | до якого сигналу |
| `text` | так | текст гіпотези |
| `factors` | ні | які фактори враховані |

**У гіпотези немає полів `lat`, `lon` і `geometry`.** Тому вона фізично не може
потрапити на карту. Це не домовленість, а властивість схеми.

## 9. Категорії

Власна таксономія, не копія переліку статей КК і КУпАП. Це важливо не лише
для зручності: **власна таксономія — один із доказів творчого упорядкування**,
на якому тримається захист авторських прав.

Верхній рівень (чернетка, уточнити на етапі 2):
- майнові
- насильницькі
- транспортні
- громадський порядок
- наркотики
- економічні
- інші

Кожна категорія має відображення на статті, і це відображення версіонується.

## 10. Користувач і збережені місця

> Схему закладаємо одразу, реалізацію — на етапі 7
> ([`rishennya/0002-monetyzatsiya.md`](rishennya/0002-monetyzatsiya.md)).

| Сутність | Ключові поля |
|---|---|
| `user` | id, email, дата реєстрації, тариф |
| `saved_place` | user_id, назва, тип (адреса+радіус / вулиця / мікрорайон / район / намальована зона), геометрія, категорії подій |
| `notification` | user_id, saved_place_id, event_id, дата події, дата появи документа, чи прочитано |

**Правило:** у сповіщенні **дата події і дата появи документа показуються
окремо**. Документ 2026 року може описувати подію 2019-го.
