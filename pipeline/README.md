# pipeline — конвєєр обробки даних

**Що тут буде:** код, який перетворює офіційний архів ЄДРСР на події з
координатами, готові до показу.

**Статус:** порожньо. Етап 3 дорожньої карти.

## Кроки конвєєра

| # | Крок | Що робить |
|---|---|---|
| 1 | завантаження | тягне дамп з data.gov.ua, обробляє тільки нове |
| 2 | розбір | витягує документи з архіву, нормалізує метадані |
| 3 | групування | збирає документи в справи |
| 4 | статус | визначає, чи набрало рішення законної сили |
| 5 | витяг події | що сталося, коли, де — з тексту рішення |
| 6 | категоризація | наша таксономія, не перелік статей |
| 7 | геокодування | адреса → координати + рівень впевненості |
| 8 | точність | правило 8 адрес: точка чи сота |
| 9 | фільтри | виключення за `docs/03-dani-i-etyka.md` |
| 10 | історія | переказ фабули людською мовою |

## Правила

- **Джерело — тільки дамп.** Скрапінг `reyestr.court.gov.ua` заборонений
  правилами сайту. Див. `docs/rishennya/0005-dzherelo-danykh.md`
- **Кожен крок читає результат попереднього і пише свій** — щоб можна було
  перезапустити з будь-якого місця
- **Ідемпотентність:** повторний запуск не дублює дані
- **Кожен крок пише метрики якості** в таблицю `pipeline_run`: скільки
  оброблено, скільки адрес знайдено, скільки геокодовано, скільки
  відфільтровано і чому
- **Повні тексти рішень не зберігаємо** — тільки посилання на оригінал

## Найскладніше

адреси в рішеннях пишуться десятками способів, плюс перейменування вулиць
